Project context
1. Project context
You have just joined a team responsible for designing the new site Campus Life, a fictional platform intended for future and new learners of Youcode.

When a learner joins YouCode, they discover not only training, but also a new environment, the objective is to design a Web experience allowing future learners to discover this universe.

---

2. General objective
Design and integrate one static and responsive website from a Figma model, while respecting:

the visual structure of the design;
HTML5 semantics;
CSS best practices;
web accessibility;
the organization of the code;
git and GitHub best practices.
---

3. Educational objectives
UI/UX and mockup playback
Through this project you must be able to:

Analyze a Figma model.
Identify the different areas of an interface.
Understand the visual hierarchy of a page.
Identify colors, spacing and typographies.
Identify reusable components.
HTML5
You must be able to:

Build the basic structure of an HTML page.
Use semantic HTML tags.
Create navigation between multiple pages.
Use titles correctly h1 has h6.
Embed images.
Create lists.
Use links and anchors.
Create accessible forms.
Correctly structure the different sections of a page.
CSS3
You must be able to:

Use suitable CSS selectors.
Handle the Box Model.
Manage colors, borders, spacing and typography.
Use display.
Build layouts with Flexbox.
Use CSS Grid when relevant.
Manage the positioning of elements.
Reuse CSS classes.
Avoid unnecessary repetition in styles.
Accessibility
The site must respect the fundamental principles of accessibility:

Use a semantic HTML structure.
Add alternative texts to images.
Use them correctly label forms.
Guarantee sufficient contrast.
Maintain understandable navigation.
Git & GitHub
You must:

Initialize a Git repository.
Create commits regularly.
Use explicit commit messages.
Publish the project on GitHub.
Organize project files correctly.

4. Pages to create

Identify:

[] The pages
[] The sections
[] Colors
[ ] Typographies
[] Spacing
[] The buttons
[] The cards

Step 2 — Zoning
Break each page down into large functional areas.

Zoning allows you to understand the structure of the page before starting its integration.

---

Create:

[] The Git repository
[] HTML files
[] CSS folders
[] The files assets
[] The README

Deliverables

1. GitHub Repository: The repository must contain all the source code, It must be correctly named and accessible.
2. README: The README must present at least: the name of the project; a short description; the technologies used; the main structure of the project; instructions for launching the site; possibly a capture of the result.
3. Presentation /Demonstration: you must be able to present your project and explain: its zoning; its HTML structure; the organization of your CSS; its use of Flexbox; its responsive approach; certain technical choices made.
Performance criteria
The project will be considered functional when the following criteria are met.
Model
The general appearance respects the Figma model. The main colors are consistent. The typographies are consistent. The main spacing is respected. The cards and buttons reflect the visual identity of the model.
HTML
Each page has a valid HTML structure. Only one main h1 tag is used per page. Titles follow a logical hierarchy. Semantic tags are used correctly. Relevant images have an alt attribute. Navigation links work. All pages are accessible from navigation.
CSS
Styles are primarily placed in external CSS files. Flexbox is used to build layouts where relevant.The Box Model is correctly mastered. Common styles are reused. Large repetitions are avoided. No important elements are positioned only with fixed absolute values.
Responsive
The site must be usable at least on:
mobile;tablet;desktop.
On mobile:
no unintentional horizontal scrolling; text remains readable; images remain adapted to the screen; sections reorganize correctly; maps can move from horizontal to vertical layout.
Navigation
All main links work. The user can return to the home page from all pages. The active page is visually identifiable. No essential links lead to a non-existent page.
Form
Each field has a label. The correct input types are used.Required fields use required when necessary. The send button is clearly identifiable.
Accessibility
Images have textual alternatives when necessary. The hierarchy of titles is logical. The contrast allows comfortable reading. The links and buttons are clearly identifiable. The structure remains understandable without CSS.
Git & GitHub
The project is versioned with Git. Several commits are present. The commit messages describe the modifications made. Unnecessary files are not versioned. The repository contains a README.The links and buttons are clearly identifiable. The structure remains understandable without CSS.
